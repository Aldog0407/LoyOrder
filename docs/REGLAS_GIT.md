# Reglas Git del equipo

1. No hacer cambios directos en `main`.
2. Trabajar en ramas `feature/...` y `fix/...`.
3. Cada Pull Request debe explicar qué se cambió y cómo se comprobó.
4. Pedir revisión de otro integrante.
5. No subir secretos ni credenciales.
6. Usar mensajes con formato `feat:`, `fix:`, `docs:`, `test:`, `refactor:` o `chore:`.
7. Integrar primero en `develop` y llevar a `main` las versiones revisadas.
